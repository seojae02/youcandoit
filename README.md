# YouCanDoIt — AI 면접 코치

> 혼자 연습하는 모의 면접에서, **말한 내용뿐 아니라 말하는 태도까지** 함께 짚어주는 웹 서비스입니다.

---

## 어떤 문제를 풀었나

면접 준비를 혼자 하면 두 가지가 막힙니다.

**첫째, 답변이 괜찮은지 알 수 없습니다.** 거울 앞에서 아무리 말해봐도 내 대답이 질문의 의도에 맞는지, 논리가 서 있는지는 스스로 판단하기 어렵습니다.

**둘째, 태도는 아예 보이지 않습니다.** 실제 면접에서 당락을 가르는 건 내용만이 아닙니다. 시선이 자꾸 흔들리는지, 어깨가 한쪽으로 기우는지, 표정이 굳어 있는지 — 정작 본인만 모릅니다. 스터디를 구해도 사람의 눈으로는 "좀 불안해 보였어요" 정도의 인상 평가에 그칩니다.

YouCanDoIt은 이 두 가지를 함께 봅니다. 자기소개서를 넣으면 예상 질문을 만들어주고, 답변하는 영상을 분석해 **시선·자세·표정을 숫자로 바꾼 뒤**, 답변 내용과 묶어 하나의 코칭 리포트를 만듭니다.

핵심은 "정확한 모델"이 아니라 **"납득할 수 있는 피드백"**입니다. "시선 이탈 12회"라는 숫자 자체보다, 그 숫자가 사용자가 수긍할 만한 기준으로 세어졌는지가 이 프로젝트의 실제 과제였습니다.

---

## 어떻게 동작하나

```
1. 자기소개서 입력
        ↓
   AI가 예상 질문 3개 생성
        ↓
2. 질문에 답변하며 영상 녹화
        ↓
   영상 분석 → 시선 · 자세 · 표정을 수치화
        ↓
3. 답변 내용 + 행동 데이터를 함께 AI에게 전달
        ↓
   논리성 / 태도 / 강점 / 개선 제안 리포트
```

영상에서 뽑아내는 지표는 네 가지입니다.

| 지표 | 의미 |
|---|---|
| 어깨 이탈 횟수 | 자세가 한쪽으로 기운 횟수 |
| 시선 이탈 횟수 | 화면 밖으로 시선이 벗어난 횟수 |
| 평균 미소 점수 | 표정의 밝기 (0~100) |
| 분당 눈 깜빡임 | 긴장도 참고 지표 |

이 숫자들이 그대로 사용자에게 보이지는 않습니다. AI가 답변 내용과 함께 읽고 **"시선 이탈이 다소 잦았어요. 카메라를 조금 더 응시해보세요"** 같은 문장으로 바꿔서 전달합니다.

---

## 이 프로젝트에서 가장 고민한 것

기능을 붙이는 것보다 **"무엇을 기준으로 셀 것인가"**를 정하는 데 시간이 훨씬 많이 들었습니다. 모델은 좌표만 알려줄 뿐, "이 정도면 시선이 벗어난 것"이라는 기준은 직접 정해야 했기 때문입니다.

### 1. 한 번 깜빡인 걸 서른 번으로 세지 않기

눈 감김 정도가 기준값 하나(예: 0.5)를 넘으면 깜빡임으로 센다고 해봅시다. 문제는 눈이 반쯤 감긴 순간입니다. 값이 0.49와 0.51 사이를 떨면서 **한 번의 깜빡임이 수십 번으로 집계**됩니다.

그래서 기준을 **두 개**로 나눴습니다.

```
0.6 이상  →  "감았다"로 판정하고 카운트
0.3 미만  →  이때 비로소 "떴다"로 복귀
```

두 값 사이에 여유 구간을 두면 경계에서 아무리 떨려도 중복으로 세지 않습니다. 같은 발상을 어깨·시선에도 적용해서, **상태가 바뀌는 순간에만** 카운트하도록 했습니다. 프레임마다 세면 30fps에서 1초만 기울어도 30회가 되기 때문입니다.

숫자를 정확하게 만드는 일보다, **사용자가 봤을 때 "그래, 내가 그 정도 했지"라고 납득하는 숫자**를 만드는 게 목표였습니다.

### 2. 길이가 다른 영상을 같은 잣대로 비교하기

깜빡임 총 횟수는 영상이 길수록 무조건 커집니다. 3분 면접과 10분 면접을 나란히 놓을 수 없습니다. 그래서 **분당 횟수로 정규화**했습니다. 미소 점수는 **얼굴이 검출된 프레임만으로** 평균을 냅니다. 전체 프레임으로 나누면 얼굴이 화면 밖에 있던 구간 때문에 점수가 부당하게 낮아집니다.

### 3. 실시간으로 못 하는 것을 인정하기

처음에는 모든 피드백을 실시간으로 주려 했습니다. 하지만 음성을 텍스트로 바꾸는 STT는 처리에 시간이 걸려서, 실시간으로 밀어붙이면 화면이 멈추고 면접 흐름 자체가 끊겼습니다.

그래서 **지연 시간을 기준으로 피드백을 두 층으로 나눴습니다.**

| | 실시간 레이어 | 사후 배치 레이어 |
|---|---|---|
| **다루는 것** | 자세, 시선, 표정, 목소리 크기·높낮이 | 답변 내용, 논리성, 종합 평가 |
| **왜 여기인가** | 변환 과정이 없어 바로 계산됨 | STT와 LLM 추론에 시간이 필요함 |
| **언제 보여주나** | 면접 중 | 면접 종료 후 |

기능을 포기한 게 아니라 **보여주는 시점을 옮긴 것**입니다. 실시간성이 필요 없는 것까지 실시간으로 만들려다 전체를 불안정하게 만드는 대신, 각 지표가 감당할 수 있는 자리에 배치했습니다.

## 기술 구성

| 영역 | 사용 기술 | 역할 |
|---|---|---|
| 웹 | Next.js 16, TypeScript | 면접 화면, 실시간 지표 표시 |
| 서버 | FastAPI, Uvicorn | REST API, 프레임·파일 분석 |
| 영상 분석 | MediaPipe (Face / Pose Landmarker), OpenCV | 홍채·어깨·표정 좌표 추출 |
| 음성 분석 | Whisper `tiny`, librosa | 음성→텍스트, 볼륨·피치 |
| 피드백 생성 | Google Gemini | 질문 생성, 종합 코칭 리포트 |

**Whisper는 API를 호출하지 않고 모델을 직접 구동합니다.** 3초 단위로 잘라 처리해야 해서 호출 비용과 네트워크 지연을 피하는 쪽을 택했고, 그만큼 정확도를 양보하는 대신 가장 가벼운 `tiny` 모델을 썼습니다.

```
web/                      Next.js — 사용자 화면
└── src/
    ├── app/              랜딩 · 면접 세션 · 결과 3페이지
    └── lib/
        ├── aiClient.ts   서버 호출 단일 창구 (한글 alias 매핑을 여기 가둠)
        ├── session.ts    페이지 간 데이터 전달
        └── speech.ts     Web Speech API 래퍼

ai_coach/                 FastAPI — 분석 서버
├── main.py               FastAPI 진입점, API 라우팅
├── video_analyzer.py     영상 → 4가지 지표 산출
├── audio_analyzer.py     마이크 → STT · 볼륨 · 피치
├── gemini_processor.py   질문 생성 및 종합 피드백 프롬프트
├── state_manager.py      스레드 간 실시간 데이터 공유
├── selftest.py           핵심 집계 로직 검증
├── static/demo.html      데모 콘솔 (동작 확인용 페이지)
└── models/               MediaPipe 모델 파일 (.task)
```

## 실행 방법

### 1) 분석 서버

```bash
cd ai_coach
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env        # GEMINI_API_KEY 입력
python main.py
```

마이크를 쓰는 음성 분석까지 돌려보려면 `pip install -r requirements-local.txt` 를 추가로 실행합니다.

### 2) 웹

```bash
cd web
npm install
cp .env.example .env.local  # 기본값이면 그대로 두면 됩니다
npm run dev
```

`http://localhost:3000` 에서 카메라 권한을 허용하면 시작됩니다.
자기소개서 없이 **기본 질문으로 시작**하면 AI 호출 없이 웹캠 평가만 확인할 수 있습니다.

### 서버 동작만 확인하려면

브라우저에서 `http://127.0.0.1:8000` 을 열면 **데모 콘솔**이 뜹니다.
스트림을 켜고 실시간 지표가 올라가는 걸 보거나, 녹화 파일을 올려 분석해볼 수 있습니다.
실제 서비스 화면이 아니라 서버 동작을 눈으로 확인하기 위한 페이지입니다.
(`/docs` 에 API 문서, `/api/health` 에 의존성 상태)

### 웹캠 없이 실시간 기능 확인하기

프론트엔드를 붙이는 동안 카메라가 없어도 실시간 경로를 테스트할 수 있도록,
영상 소스를 파일로 바꿀 수 있게 해뒀습니다.

```bash
VIDEO_SOURCE=/경로/면접영상.mp4 python main.py
```

이렇게 띄우면 `/video_feed` 가 그 영상을 웹캠처럼 재생하면서 실제로 지표를 계산하고,
`/api/analysis` 로 값이 올라옵니다. 영상이 끝나면 처음부터 다시 재생합니다.

### 핵심 로직 검증

```bash
cd ai_coach && python selftest.py
```

임계값 판정과 집계 로직은 모델이 정답을 주지 않고 직접 정해야 했던 부분이라,
MediaPipe 없이 따로 돌려볼 수 있는 테스트를 만들어 뒀습니다.
히스테리시스·상태 전이 집계·정규화·스레드 안전성까지 10개 항목을 검사합니다.

### 환경 변수

| 이름 | 기본값 | 설명 |
|---|---|---|
| `GEMINI_API_KEY` | — | Gemini API 키 (`ai_coach/.env`) |
| `VIDEO_SOURCE` | `0` | `0`은 웹캠, 파일 경로를 주면 그 영상을 사용 |
| `REALTIME_DETECT_EVERY` | `3` | 실시간에서 몇 프레임마다 추론할지 |
| `BATCH_FRAME_STRIDE` | `1` | 녹화 분석 시 프레임 건너뛰기 |
| `ALLOWED_ORIGINS` | — | 쉼표로 구분한 프론트 주소. 지정하면 쿠키 인증 허용 |

> **참고**
> `.env` 와 모델 파일 경로가 실행 위치를 기준으로 잡히므로 `ai_coach/` 안에서 실행해야 합니다.
> MediaPipe 는 `1.0.x` 가 macOS 에서 Metal 초기화에 실패해 크래시하므로 `0.10.x` 로 고정했습니다.
> 음성 분석은 `pyaudio` 설치가 까다로워 선택 기능입니다. 없어도 서버는 정상적으로 뜹니다
> (macOS: `brew install portaudio` 후 `pip install pyaudio`).

## API

| 메서드 | 경로 | 하는 일 |
|---|---|---|
| `POST` | `/api/generate-questions` | 자기소개서 → 예상 질문 3개 |
| `POST` | `/api/analyze-frame` | 프레임 1장 → 누적 지표 (브라우저가 1초마다 호출) |
| `POST` | `/api/analyze-video` | 영상 파일 → 4가지 행동 지표 |
| `POST` | `/api/final-feedback` | 질문·답변 + 행동 지표 → 종합 리포트 |
| `GET` | `/video_feed` | MJPEG 스트림 (내보내면서 동시에 분석) |
| `GET` | `/api/analysis` | 실시간 지표 조회 (프론트가 폴링) |
| `POST` | `/api/session/reset` | 새 면접 시작 시 누적값 초기화 |
| `POST` | `/api/audio/start` · `/stop` | 실시간 음성 분석 제어 |
| `GET` | `/api/health` | 서버·의존성 상태 확인 |

`/api/analyze-frame` 과 `/api/analyze-video` 는 **같은 `FrameAnalyzer` 를 공유합니다.**
두 경로가 각자 판정 로직을 가지면 같은 영상인데도 화면에 뜨는 숫자와 최종 리포트의
숫자가 어긋납니다.

`/video_feed` 는 서버가 웹캠을 직접 여는 경로라 카메라가 없는 환경에서는 동작하지
않습니다. 웹 화면은 브라우저가 카메라를 소유하고 `/api/analyze-frame` 으로 프레임을
보내는 방식을 씁니다.

## 현재 구현 범위

솔직하게 적어둡니다.

| 기능 | 상태 |
|---|---|
| 자기소개서 기반 예상 질문 생성 | ✅ |
| 녹화 영상 종합 분석 (4가지 지표) | ✅ |
| 답변 + 행동 데이터 결합 코칭 리포트 | ✅ |
| 프레임 단위 실시간 지표 산출 | ✅ |
| **면접 화면 (질문 → 답변 → 결과)** | ✅ `web/` |
| 답변 받아쓰기 (Web Speech API) | ✅ Chrome · Edge |
| 실시간 음성 분석 (STT·볼륨·피치) | 🔸 구현돼 있으나 기본 흐름에 미연결 |
| 데모 콘솔 (서버 동작 확인용) | ✅ `/` |
| **배포** | ⏳ 미완 |

**AI 호출은 사용자가 누를 때만 일어납니다.** 웹캠 평가는 LLM 을 전혀 쓰지 않고,
질문 생성과 코칭 리포트만 Gemini 를 호출합니다. 기본 질문으로 시작하면 AI 호출 없이
평가 기능만 쓸 수 있습니다.

음성 분석(`audio_analyzer.py`)은 서버가 마이크를 직접 열어야 해서 기본 흐름에서 빼두었습니다.
답변 텍스트는 브라우저 Web Speech API 로 받습니다.

### 알고 있는 한계

- **동시 사용자 1명 기준입니다.** 웹캠은 자원이 하나뿐이고, 실시간 지표도 전역에 하나만
  유지합니다. 여러 명이 동시에 면접을 보려면 세션 단위로 상태를 분리해야 합니다.
  (MediaPipe 추론 자체는 락으로 보호해 두어 동시 요청에도 깨지지 않습니다.)
- **긴 영상은 분석에 시간이 걸립니다.** 기본값이 모든 프레임을 처리하는 설정이기 때문입니다.
  `BATCH_FRAME_STRIDE` 로 건너뛸 수 있지만, 깜빡임은 0.1~0.4초짜리 짧은 이벤트라
  건너뛰면 놓칩니다. 지표별로 처리 주기를 다르게 가져가는 것이 다음 과제입니다.
- **임계값은 실험적으로 정한 값입니다.** 제한된 환경에서 반복 테스트로 맞췄을 뿐,
  조명이나 카메라 각도가 달라지면 다시 조정해야 합니다.
